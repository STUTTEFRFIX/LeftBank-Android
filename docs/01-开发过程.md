# 开发过程

## 起点

需求只有一句话：让 Claude 的工作状态像灵动岛一样挂在屏幕边上，随时能看，随时能点。

最初的版本是一个自由悬浮的矩形窗口（34×178dp），带额度圆环、Bot 动画、磁吸和惯性。它被否掉了三次：

1. **太长**——34×178dp 在 6.7 寸屏上像一块牌子；
2. **位置太死**——只能贴着左边滑；
3. **主角变成了胶囊**——它不像「灵动岛」。

## 折返：从悬浮到贴边

最后定下来的模型是：

- **只活在边框上**：屏幕一圈按圆角矩形路径参数化，位置用弧长 `s` 表示；
- **收起是一条线**，**展开是沿路径的胶囊**，都贴着边框；
- **拐角自动弯折**：胶囊不是矩形，而是沿路径偏移 15dp 再描 30dp 粗的线，所以过拐角时会跟着圆弧走；
- **线不能拖，展开后能拖**：拖动沿路径平移，过拐角自动换向。

## 踩过的坑（按时间）

### 1. 拐角处窗口尺寸一变，手势就断

悬浮窗在拐角需要换尺寸，`updateViewLayout` 一改大小，系统会把正在拖的手势 CANCEL，看起来像「拖一半被弹回去」。

- 修法：手势进行中完全不动窗口；只在松手、惯性结束、吸附完成之后，按最终位置给一次余量。

### 2. 磁吸只在松手时判断

手指还按着、进范围不吸；一抖就出范围，松手就不动——看起来像「被弹开」。

- 修法：拖动中一进范围就播一段 160–280ms 的减速动画吸到边上；往外拉可以中途打断。

### 3. 画错地方的箭头

`‹` 收回把手的几行代码被插进了「收起时画线」的方法里，于是收起的线上顶着一个箭头。

- 教训：`drawLine` 和展开分支是两个方法，**改动前先看它在哪个方法里**。

### 4. 胶囊没了

换边框渲染时只画了图标，把展开时的胶囊底和描边整个漏了。用户原话：「我问你 胶囊呢？」

- 修法：沿路径偏移 15dp 描 30dp 的圆头线当胶囊，再描一圈 1.4dp 的浅色边。

### 5. 接入网关一直被 403

`curl /api/state` 一直是 `{"error":"forbidden"}`。网关的校验不止 Host：

- 还有 `X-CC-Token`（64 位，存在 cc 私有目录，0600，别的应用读不到）。
- 修法：把令牌拷到本应用自己的媒体目录，应用读自己的媒体目录不需要存储权限。

### 6. 面板接上了，但一直显示「空闲」

真因不是接口，是 **Android 默认禁止明文 HTTP**：

```
java.io.IOException: Cleartext HTTP traffic to 127.0.0.1 not permitted
```

- 修法：清单加 `android:usesCleartextTraffic="true"`。

### 7. 选项文字溢出按钮

选择题的选项可能很长，按钮只有 96dp 宽。

- 修法：按当前画笔量宽，超出就截断加 `…`，并把绘制裁剪在按钮矩形内；回写仍用完整文字。

## 取舍

- **不做输入框**：悬浮窗里弹输入法要切窗口焦点模式，容易做成「点了没反应」的半成品，暂不接；
- **轮询而不是 SSE**：2 秒一次的 `/api/state` 够用，实现短、断线自愈；
- **只显示一个 agent**：真实数据只有 cccodroid 一家，不摆空位。

## 第二阶段（2026-10-27 晚）：从聊天窗到监察窗

第一版做了一扇聊天窗（消息列表 + 输入框 + `/api/chat`）和一个信息卡片。主人在真机上用了半天，给出两条结论：

1. 胶囊滑到底部会和面板重叠；面板跟着走的时候应该抬开，不能挤在一起；
2. **不要聊天窗**。把它改成「回复和监察 AI 状态以及工作」的窗口；需要选选项或确认权限时就引用它。「对话框的内容相关功能全部去掉，只保留其 UI 和操作逻辑」。

于是有了现在的 `MonitorWindow`：没有消息历史、没有输入框，也不碰 `/api/chat`、`/api/session`；只显示状态 / 模型 / 余额 / 今日 / 本轮，并把待处理请求画成按钮。加号也从胶囊上去掉，胶囊跨度从 `n*44 + 46dp` 收到 `n*44 + 24dp`。

### 8. 底部的「重叠」：少了手势区

路径底边原来只取 `navigationBars`。沉浸模式下它返回 **0**，可底部还有一条 **32dp 的手势区**（`mandatorySystemGestures`，这台机器 112px）。胶囊就压在上滑手势里。

- 修法：`getInsetsIgnoringVisibility(statusBars|navigationBars)`，底边再取 `max(navigationBars, mandatorySystemGestures)`；底部路径 2772 → 2639，手势区 2660 起。
- 顺带：胶囊在下边框时，状态字画到图标**上方**（朝屏幕内侧）。

### 9. 角上的「月球撞地球」：支撑半径不够

主人给了个准确的比喻：胶囊和面板要像地球和月亮，距离不变；重叠就是月球坠入地球。

第一版用「沿内法线偏移 + 矩形支撑半径」：面板中心 = 胶囊中心 + `n*(30dp + 14dp + support)`。直边很好，四角却还是碰——灯带不是细线，是绕在拐角上的**厚弧**；沿法线留 14dp 只保证法线方向，面板的**近角**会从切向扎进那圈弧里（底左角实测近角到弧心 60px，弧从 35px 到 140px，正好在灯带里）。

- 修法：把灯带中心线（偏移 15dp、半径 15dp）采样 25 点，算「点到矩形」距离；小于 `15dp + 14dp` 就沿「胶囊中心 → 面板中心」的方向把面板推出去，最多 8 次。
- 结果：底左角面板从 `(214,1372)` 推到 `(241,1342)`，最近距离 109px（need 102px），离灯带边约 16dp；直边仍是 49px = 14dp。

> 参考了 `jazzenchen/agent-hud-open`：`src/packages/hud/src/geometry.ts` 的 `cardRect()` detached 分支就是「面板在条子内侧、留固定 gap、沿轴居中」；`HUDExpandedSurface` 用 `transformOrigin` 从条子那一侧长出来。这里的 14dp 和缩放支点都是照着它学的。

### 10. 触控范围不能是整块窗口

展开窗口原来是 220dp 方块、收起窗口留 24dp 边距；窗口里任何一点都算触摸，点空白就收起，收起时点旁边一大片也会展开。主人原话：「胶囊的触控范围也太大了吧，应该是紧贴着胶囊体积吧」。

- 展开窗口 220dp → **140dp**；收起边距 24dp → **10dp**。
- `nearCapsule()` 同时查：
  - 离灯带的垂直距离：展开 34dp（30dp 灯带 + 4dp 余量），收起 18dp；
  - 沿路径方向：不超过 `胶囊半跨 + 10dp`——不是整条边框都算。
- 手指不在胶囊上：不展开、不收起、不拖动；图标仍点一下开 / 关监察窗；胶囊上的空白仍点一下收起。
- 实测：底左角沿下边框离开胶囊 60dp 点一下，胶囊与监察窗都不动；点图标，监察窗收起、胶囊保持展开。

真正的「窗口外透传」需要 `ViewTreeObserver` 的 touchable region（隐藏 API，SDK 里没有）。这一版先用「小窗口 + 命中判定」顶着：140dp 窗口内、胶囊外的点击不会传给下面的应用，但至少不会误触胶囊。

### 11. 聊天窗时代的坑，留给后来人

- 悬浮窗一改尺寸，正在拖的手势会被 CANCEL（第二阶段的 140dp 是**固定尺寸**，所以不触发）；
- 网关要 `X-CC-Token`，明文 HTTP 要在清单里放行；
- 选项文字会溢出按钮，要按画笔宽度截断 + `clipRect`，回写仍用完整文字；
- 对话窗打开时没在 `addView` 后调用放置方法，窗口会停在 `(0,0)` 压住胶囊。

## 取舍

- **不做聊天输入**：第一版做过，后来按主人要求整个删掉了——监察窗只负责看和作答；
- **轮询而不是 SSE**：2 秒一次的 `/api/state` 够用，实现短、断线自愈；
- **只显示一个 agent**：真实数据只有 cccodroid 一家，不摆空位。

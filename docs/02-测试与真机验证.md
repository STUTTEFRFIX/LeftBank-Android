### 旧版（卡片 / 聊天窗）验证过、现在仍适用的链路

- **选择题（AskUserQuestion）**：用两次真实的 `AskUserQuestion` 验证过整条链路：`perm_request` → 面板显示 → 面板点选 → `POST /api/perm/answer`（`answers: {问题: 选项}`）→ Claude 收到。第二次故意用很长的选项文字，面板显示截断，回写的是完整标签。
- **权限确认**：允许 / 拒绝走 `POST /api/perm/answer`（`behavior: allow/deny`）；`always: true` 接口早已接上，当前监察窗把「始终允许」画成了第三个按钮。

> 改成监察窗后，选项来源从两个固定字段变成列表、按钮从卡片搬到监察窗；**接口和字段没变**，但还没有重新跑一轮真实的端到端回归（见「未验证」）。

### 关键测量（adb `dumpsys window`）

- 手势区：`mandatorySystemGestures` 底 112px（32dp）；路径底边 2639；胶囊灯带底 2640。
- 直边：左边中胶囊 `(21,1400)`，监察窗 `(175,823)`，间隙 49px = 14dp。
- 底左角：胶囊 `(68,2604)`，监察窗 `(241,1342)`；灯带中心线到矩形最近 109px，`need = 15dp + 14dp = 102px`。
- 展开窗口：140dp（490px）；收起窗口边距 10dp。

## 未验证 / 已知问题

- 其他 ROM（HyperOS / OriginOS / 原生 Android）的悬浮窗与手势行为未测；
- 监察窗上的真实 `AskUserQuestion` / 权限作答还没重新做端到端回归（接口未变，旧版通过）；
- 多轮 `runs[]` 与 SSE 步骤未接；仍是 2 秒轮询，请求最多延迟 2 秒；
- 窗口外真正的点击透传没做（需要隐藏 API `ViewTreeObserver` 的 touchable region，SDK 里没有）；现在是 140dp 小窗 + 命中判定，窗口内、胶囊外的点击不会传给下面的应用，但不会误触胶囊；
- 设置页里的「磁吸范围」滑杆已经无意义，尚未移除。
